## D1　路由前缀不统一（B2）🔴 必须定

**现象：** 两套前缀并存，源于芋道包名匹配规则。

| 侧 | 包路径 | 实际前缀 | 条数 |
| --- | --- | --- | --- |
| 乙（M3/M4/M5/M7） | `controller.v1.**` | `/api/v1/**` | 35 + 4(admin) |
| 甲（M1/M2/M6） | `controller.app.**` | `/app-api/mate/**` | 15 |
| 甲（M1/M2/M6） | `controller.admin.**` | `/admin-api/mate/**` | 11 |
| 内部 | `controller.v1.**` | `/internal/v1/**` | 1 |

**为什么甲侧改不了：** 芋道框架按包名 `**.controller.app.**` 自动加 `/app-api`，乙侧包名是 `controller.v1`，不匹配，加不上。

**三个选项：**

| 方案 | 做法 | 代价 | 推荐 |
| --- | --- | --- | --- |
| **A 双 baseURL** | 前端请求层配两个 baseURL，按模块路由 | 前端多一层封装，成本最低 | ✅ **推荐** |
| B 加网关改写 | nginx 把 `/api/v1` 改写到 `/app-api/mate` | 多一个组件，演示环境多一处可能出错 | ❌ |
| C 统一包名 | 乙侧改包名到 `controller.app` | 动 20 个控制器，回归风险大，工期不允许 | ❌ |

**结论：选 A。** 前端请求层：

```ts
const BASE_APP   = 'http://host:48080/app-api/mate'    // M1/M2/M6
const BASE_ADMIN = 'http://host:48080/admin-api/mate'  // 后台
const BASE_V1    = 'http://host:48080/api/v1'          // M3/M4/M5/M7
```

## D3　36 张表实际只有 32 张（🟠 文档需修正）

**缺失的 4 张：**

| 表 | 文档声称用途 | 实际 |
| --- | --- | --- |
| `mida_idempotency` | 写接口幂等首次结果 | ❌ **不存在**，全仓库 0 处引用 |
| `mida_event_outbox` | 事件发件箱，与事务同提交 | ❌ **不存在** |
| `mida_event_consumed` | 消费去重 | ❌ **不存在** |
| `sys_config` | 套餐/限额/权重集中配置 | ⚠️ 有定义但**限额未走它**（硬编码在 `TransferLimits`） |

**幂等实际怎么实现的：** 不落表，靠 `Idempotency-Key` 派生业务单号 + 数据库唯一约束。

```java
// TransferServiceImpl.java:307-310
String digest = sha256Hex(payerId + ":" + idempotencyKey);
return "T" + digest.substring(0, 24).toUpperCase();
```

**结论：** 文档删掉 3 张表，或标注"设计规划，未实现"。**选标注**，因为它们反映了架构意图，只是本期未做。

## D4　TC-07 用 L4，但 L4 不存在（🟠 用例需改）

| 项 | 文档 | 代码 |
| --- | --- | --- |
| TC-07 | "双 L4，单笔=500，通过" | `AuthLevelAspect.java:35`：`if (authLevel < require) throw 1003` |
| L4 | 规划"不做，留接口桩" | **无任何 L4 豁免逻辑** |

**影响：** 若有 L4 用户，`authLevel=4 >= 2` 能过等级闸门，但**系统里根本没有 L4 数据**。这条用例设计上无法执行。

**建议：** TC-07 改为 **"双 L2 单笔=2000 通过"**（测上限边界，这才是它想测的）。
